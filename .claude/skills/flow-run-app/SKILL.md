# Flow 앱 실행해서 화면에 띄우기

사용자가 말하는 "확인할 수 있게 보여줘 / 웹으로 확인"은 **앱을 실제로 실행해서 화면에 띄우라는 뜻**이다. 브라우저 웹 빌드가 아니다.

## 언제

- 앱 코드(lib/, assets/, pubspec.yaml, windows/)를 바꾼 작업이 끝나면 **묻지 말고 항상** 실행한다.
- 순서: `flutter analyze lib test` / `flutter test` 통과 → 관련 스킬 갱신 → 버전 올리기(flow-versioning) → 커밋 → `git push`(현재 작업 브랜치 + 버전 태그, origin) → 앱 실행.
- 띄운 창은 모니터 작업 영역 안에 들어와야 한다(제목줄이 보여서 마우스로 옮길 수 있어야 함). 넘치면 flow-window 규칙을 확인한다.
- 실행 후 창 제목에 `Flow vX.Y.Z`가 새 버전으로 보이는지 확인하라고 알려준다.
- 문서·설정만 바꿨으면 실행하지 않는다.

## 실행 전에 명령한 것부터 확인한다 (2026-11-28 사용자 지시 "실행하기 전 명령한 것에 대해 확인 후 실행해라")

- 앱을 띄우기 **전에** 사용자가 이번에 요청한 동작이 실제로 되는지 먼저 확인한다. analyze/test 통과만으로 끝내지 않는다.
- 확인 방법: 요청한 동작을 직접 재는 **위젯 테스트를 추가**해 (1) 새 코드에서 통과하고 (2) 예전 코드(`git show vX.Y.Z:파일 > 파일` 후 테스트, 끝나면 `git checkout HEAD -- 파일`)에서는 실패하는지 본다. 둘 다 맞아야 "확인했다"고 말한다.
  - 예: 알아차림 스크롤바와 폭 조절 드래그 영역이 겹침(v1.7.6) → `test/auto_layout_test.dart`에서 ListView 오른쪽 10px(스크롤바)과 `resizeLeftRight` MouseRegion이 겹치지 않는지 검사. v1.7.5 코드에서 실패, v1.7.6에서 통과.
- 답변에 "확인: 무엇을 어떻게 확인했는지(테스트 이름, 예전 코드 실패 여부)"를 한 줄로 쓴다. 테스트로 잴 수 없는 것(색·느낌)은 확인하지 못했다고 말한다.
- 사용자가 "실행"만 말해도, 직전 작업이 확인되지 않았으면 확인부터 하고 띄운다.
- 앱이 이미 떠 있는데 "실행"이라고 하면 창이 안 보이는 것일 수 있다. 다시 띄우면서 확인되지 않은 부분을 먼저 확인한다.

## 하는 법

```
python tools/run_app.py              # 릴리스 빌드(약 25초) 후 실행
python tools/run_app.py --skip-build # 빌드 없이 바로 실행
```

- 이미 떠 있는 개발용 Flow(`build\windows\x64\runner\Release\flow.exe`)는 닫고 새로 띄운다. 빌드 중 exe가 잠기는 것을 막기 위해서다. 배포용 `dist\Flow.exe`로 실행 중인 창은 건드리지 않는다.
- `flutter build windows --release`가 exit 1로 실패하면 원인을 찾기 전에 **한 번 그대로 다시 실행**한다. 2026-11-24 첫 실행은 실패했지만 바로 다시 하니 성공했다(닫힌 exe 잠금이 늦게 풀린 것으로 보임). 2026-11-25에도 첫 빌드가 `windows\flutter\ephemeral\cpp_client_wrapper\*.cc: No such file or directory`(C1083)로 실패했고, 다시 실행하자 ephemeral 파일이 새로 생성되며 성공했다. 이 오류도 재시도만 하면 된다. 2026-11-26에도 코드 변경 없이 그냥 실행했을 때 같은 C1083이 첫 빌드에서 났고 재시도로 성공했다(3번째 재발 — 첫 빌드 실패는 정상으로 보고 바로 재시도한다). 두 번째도 실패하면 그때 `flutter build windows --release`의 출력을 직접 본다.
- 끝나면 "앱을 화면에 띄웠다"와 무엇을 확인하면 되는지(바뀐 기능, 눌러볼 버튼)를 짧게 알려준다.
- 실행만 했고 내가 직접 조작해 보지 않았으면 그렇다고 말한다.

## 참고

- 배포용 단일 exe는 flow-build-exe 스킬(`python tools/build_exe.py`).
- 웹 빌드(`tools/preview_web.py`)는 사용자가 명시적으로 "브라우저/웹 빌드"를 요청할 때만 쓴다. 웹에서는 저장·불러오기·폴더관리·창 관리·단축키가 동작하지 않는다.
